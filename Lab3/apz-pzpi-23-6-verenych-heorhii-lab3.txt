2 ХІД ВИКОНАННЯ РОБОТИ

2.1 Загальний опис web-застосунку

Система SportManager призначена для автоматизації основних процесів спортивного
клубу. Web-застосунок виконує роль основного робочого інтерфейсу для персоналу
клубу та гравців.

Архітектура web-частини побудована за клієнт-серверним принципом:
– React web-застосунок → REST API backend → PostgreSQL database

Для реалізації web-частини використано React 19 з Vite 8 як збирачем.
HTTP-запити виконуються через власний fetch-клієнт (utils/api.js) з JWT-токеном.
Маршрутизація — через React Router DOM 7. Стилі — у єдиному App.css.

--------------------------------------------------------------------------------

2.2 Опис ролей користувачів web-застосунку

У web-частині системи реалізовано три ролі:
– адміністратор (admin) — повний доступ + управління правами;
– тренер (coach) — управління клубом (команди, гравці, події, відвідуваність,
  статистика, медпункт, інвентар);
– гравець (player) — особистий кабінет із власними даними.

2.5 Реалізація взаємодії web-застосунку з backend

API-клієнт у utils/api.js автоматично підставляє JWT-токен з localStorage.
При статусі 401 — очищення сесії та перехід на /login.

API-клієнт надає методи: api.get, api.post, api.put, api.delete.
Базова адреса: /api → Vite proxy → http://localhost:3000.

Реалізовані запити до backend:
– POST /auth/login — авторизація;
– GET /dashboard — агреговані KPI;
– GET, POST, PUT, DELETE /teams, /players, /events, /stats, /injuries, /inventory;
– GET, POST, PUT /attendance;
– GET, PUT /admin/users;
– GET /profile, /profile/events, /profile/stats, /profile/attendance, /profile/team.

2.6 Реалізовані функції web-застосунку

– Авторизація з визначенням ролі та перенаправленням до кабінету;
– Пошук та фільтрація на стороні клієнта через useMemo() без запитів до API;
– CRUD через модальні вікна з валідацією та оновленням стану;
– Захист маршрутів через ProtectedRoute та AdminRoute;
– CSV-експорт відфільтрованих таблиць;
– Адаптивна верстка з гамбургер-меню на мобільних пристроях.

2.7 Локалізація web-застосунку

Код web-застосунку SportManager

utils/api.js — HTTP-клієнт:
const BASE = '/api';
async function request(endpoint, options = {}) {
    const token = localStorage.getItem('token');
    const res = await fetch(`${BASE}${endpoint}`, {
        ...options,
        headers: {
            'Content-Type': 'application/json',
            ...(token && { Authorization: `Bearer ${token}` }),
            ...options.headers,
        },
    });
    if (res.status === 401) {
        localStorage.removeItem('token');
        localStorage.removeItem('user');
        window.location.href = '/login';
        return res;
    }
    return res;
}
export const api = {
    get:    (url)       => request(url),
    post:   (url, data) => request(url, { method: 'POST',   body: JSON.stringify(data) }),
    put:    (url, data) => request(url, { method: 'PUT',    body: JSON.stringify(data) }),
    delete: (url)       => request(url, { method: 'DELETE' }),
};

context/AuthContext.jsx — управління сесією:
import { createContext, useContext, useState } from 'react';
const AuthContext = createContext(null);
export function AuthProvider({ children }) {
    const [user, setUser] = useState(() => {
        try { return JSON.parse(localStorage.getItem('user')); } catch { return null; }
    });
    const login = (userData, token) => {
        localStorage.setItem('token', token);
        localStorage.setItem('user', JSON.stringify(userData));
        setUser(userData);
    };
    const logout = () => {
        localStorage.removeItem('token');
        localStorage.removeItem('user');
        setUser(null);
    };
    return <AuthContext.Provider value={{ user, login, logout,
        isCoach: user?.role === 'coach' || user?.role === 'admin',
        isAdmin: user?.role === 'admin' }}>{children}</AuthContext.Provider>;
}
export const useAuth = () => useContext(AuthContext);
