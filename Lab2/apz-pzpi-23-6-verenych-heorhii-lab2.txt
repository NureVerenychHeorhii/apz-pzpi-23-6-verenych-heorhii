1 ЗАВДАННЯ

Метою лабораторної роботи є розробка мобільного застосунку для системи
управління спортивними командами SportManager на платформі Android. Застосунок
надає гравцям, тренерам та адміністраторам зручний доступ до функціонального
серверного API системи через мобільний інтерфейс.

У межах роботи необхідно виконати такі завдання:
– спроєктувати архітектуру мобільного застосунку;
– розробити UI/UX усіх екранів застосунку;
– реалізувати взаємодію з REST API сервера за допомогою Retrofit2;
– реалізувати авторизацію користувача з JWT-токеном;
– забезпечити рольовий доступ (гравець, тренер, адміністратор);
– розробити UML-діаграми: прецедентів, компонентів, пакетів, діяльності;
– провести тестування застосунку на емуляторі Android.

================================================================================

2 НАЗВА ТА КОРОТКИЙ ОПИС

Назва застосунку: SportManager Mobile.

SportManager Mobile — це Android-застосунок, розроблений на мові програмування
Kotlin, що забезпечує мобільний доступ до серверної частини системи управління
спортивними командами SportManager. Застосунок дозволяє авторизованим
користувачам переглядати персональну інформацію, статистику ігор, розклад
подій, медичні дані та інформацію про склад команди.

Основні характеристики застосунку:
– платформа: Android (minSdk 26, targetSdk 34);
– мова програмування: Kotlin;
– взаємодія з API: Retrofit2 + OkHttp3;
– авторизація: JWT-токени зі збереженням у SharedPreferences;
– UI-компоненти: Material Design 3, BottomNavigationView, RecyclerView;
– асинхронність: Kotlin Coroutines + ViewModel.

3 ОПИС ВИКОНАНОЇ РОБОТИ

3.1 Архітектура мобільного застосунку

Мобільний застосунок SportManager Mobile побудований за принципами розподілу
відповідальності та шаруватої архітектури. Проєкт складається з трьох
основних шарів: шар даних, шар UI та ресурси.

Шар даних містить такі компоненти:
– data.model — класи-моделі даних (Models.kt) з анотаціями Gson;
– data.network — інтерфейс ApiService та синглтон RetrofitClient;
– data.prefs — SessionManager для збереження JWT-токена.

Шар UI побудований на основі фрагментів:
– LoginActivity — екран авторизації;
– MainActivity — головна активність із BottomNavigationView;
– 6 фрагментів: Dashboard, Events, Stats, Medical, Team, Profile.

Базова URL-адреса: http://10.0.2.2:3000/ (хост-машина з Android-емулятора).

ДОДАТОК А
Код мобільного застосунку SportManager Mobile

SessionManager.kt:
class SessionManager(context: Context) {
    private val prefs = context.getSharedPreferences(PREF_NAME, Context.MODE_PRIVATE)
    companion object { const val PREF_NAME = "sport_manager_session" }
    fun saveToken(token: String) = prefs.edit().putString("token", token).apply()
    fun getToken(): String? = prefs.getString("token", null)
    fun getBearerToken() = "Bearer " + (getToken() ?: "")
    fun clearSession() = prefs.edit().clear().apply()
}

ApiService.kt:
interface ApiService {
    @POST("auth/login")
    suspend fun login(@Body request: LoginRequest): Response<LoginResponse>

    @GET("profile")
    suspend fun getProfile(@Header("Authorization") token: String): Response<ProfileData>

    @GET("profile/events")
    suspend fun getMyEvents(@Header("Authorization") token: String): Response<List<Event>>

    @GET("injuries")
    suspend fun getMyInjuries(@Header("Authorization") token: String): Response<List<Injury>>
}

LoginActivity.kt (fragment):
lifecycleScope.launch {
    val response = RetrofitClient.api.login(LoginRequest(email, password))
    if (response.isSuccessful) {
        val body = response.body()!!
        sessionManager.saveToken(body.token)
        sessionManager.saveRole(body.user.role)
        startActivity(Intent(this@LoginActivity, MainActivity::class.java))
        finish()
    } else {
        Toast.makeText(this@LoginActivity, "Помилка авторизації", Toast.LENGTH_SHORT).show()
    }
}
